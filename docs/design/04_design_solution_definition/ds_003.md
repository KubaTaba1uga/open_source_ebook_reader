## Initialize application

Goal of initialization is to do as little as possible to ensure that application is operational.

We can query display but lets not display anything, cause displaying is pretty blocking and take long, lates try to make init as fast as possible.

If init fail we should display some info that application unable to start add error info then poweroff.

## Import books

The real issue here is that we need to design page rendering pipeline to understand how book import should look like.

So for now we support only PDF, so let's benchmark each engine for 150dpi image:
- PDFium (53ms)
- MuPDF (122ms)
- Poppler+Glib (50ms)

Let's pick Poppler+Glib.

To understand how we can properly render the page in black and white we need to establish some baseline pdftoppm:
```
/usr/bin/pdftoppm -f 50 -l 50 -r 150 -png -mono /mnt/sdcard/Operating_Systems_From_0_to_1.pdf > output_pdftoppm.png
```

![Pdftoppm print](/design/assets/pdftoppm.png)

Vs `MagickAdaptiveThresholdImage(wand, 25, 50, -50)` + `MagickAutoThresholdImage(wand, OTSUThresholdMethod)`, you can find it in `ds_003_poppler_pipeline.c`.

![Our own print using magicka](/design/assets/magick.png)

Using image magick allow us to fine tune conversion to black and white. 

Beofre using image magicka `AdaptiveThresholdImage` we checked different dithering algorithms, but issue with dithering is that it is very resolution dependent and on smaller res like 1872x1404 it looks like shit.

Propably we can find better adaptive threshold alhorithm, maybe Sauvola or Wolf or Su or NICK?
