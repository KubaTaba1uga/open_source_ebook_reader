## Import books

The real issue here is that we need to design page rendering pipeline to understand how book import should look like.

So for now we support only PDF, so let's benchmark each engine for 150dpi image:
- PDFium (53ms)
- MuPDF (122ms)
- Poppler+Glib (50ms)

Let's pick Poppler+Glib.

So let's start designing our PDF engine pipeline by understanding what our options are. 
First we need ti distinguish between rendering PDF page as image and overflowing text and images on our own.
Rendering PDF page as image is simpler to implement but has worse performance and produce worse readibility,
however it works on all documents event the scanned images.
Overflowing pdf page assumes we extract text and images and we try to render it on our own using our own font 
and page layout.
Because we are just beginning the project and i want to have working prototype relatively fast we will go with Rendering PDF page as image.

Our pipeline when rendering a page looks sth like this:
```
Render a page using scaling 2.0 -> Apply adaptive thresholding -> Apply Auto Thresholding -> Done
```

We considered also other pipelines using dithering but issue with dithering is that it is
very resolution dependent and on smaller res like 1872x1404 text is unreadable, images however look great. 
We also tried non adaptive thresholding but then images look bad.

So the question is now what libs and parameters use for the pipeline.
As lib we use ImageMagicka as it is pretty stable and mature and gives us all necessary algos.

Next question is what parameters to use? In `MagickAdaptiveThresholdImage` we need to specify size of the matrix used to determine each pixel
color. The size of the matrix affect time of the pipeline significantly, however bigger sizes look usually better to some point then readibility
stagnates, from what i saw sweet spot is around 30x60 or 50x50.

## Open book reader

We want to display battery and time on the upper bar.

Additionally we should be able to configure whether we want to see number of the page and max number of pages on the upper bar.

Below the bar we want the page of the book.

We want to allow opening book settings and changing it for example scale and x/y offset and whether display number of the page or max number of pages,
propably change page would also be nice to jump quickly from 1st page to 200th.

It can take a long time to render a page, so we need to somwhow hide this processing time. When we open a book, we post a search for a last read page of the book.
This search trigger ensuring that we have +3 pages from current one. If we have a match library return a page and broadcast page found, if not the rendering job
will trigger page found when page is rednered. Similiarly it works when we change a page reader broadcast search, if we have a match library return found,
if we do not have instant match the job will render the page at some point and return it. In case when we do not have an instant match we can display sth like
`Rendering page...`. In any case we need to be able to defer sth to the external thread and wait until it will return us found or not found.
